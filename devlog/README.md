# 开发日志（devlog）

本目录是「历史粘贴（ClipHistory）」项目**开发进度与待办事项的唯一真源**。

## 目录内容

| 文件 | 作用 |
|---|---|
| [`开发索引.md`](开发索引.md) | 阶段进度总表：每个阶段的状态与一行结论 |
| [`待办事项.md`](待办事项.md) | 唯一待办清单，编号 `P<阶段>-<序号>`，按阶段分组 |
| [`sessions/`](sessions/) | 逐阶段的会话记录，一个阶段一条 |
| [`sessions/_模板.md`](sessions/_模板.md) | 会话记录模板，新建记录时复制它 |

## 什么时候写

| 时机 | 写什么 |
|---|---|
| **阶段完成** | 一条会话记录 + 更新开发索引 + 更新待办事项 |
| **阶段受阻** | 一条会话记录：阻塞点、已试方案、需要什么决策 |
| **中途发现重要问题** | 追加到 `待办事项.md`，不必单独写会话记录 |
| 日常零碎改动 | **不写**。日志只记阶段级节点，避免流水账淹没重点 |

## 硬性纪律

1. 每阶段收尾**必须**完成：验证 → 写会话记录 → 更新索引与待办 → 同步标准文件 → 提交。
   五步未完成，**不得**开始下一阶段。
2. 一个阶段**一条**会话记录，不合并、不跨阶段混写。
3. 待办编号一经分配**不复用**；已放弃的条目标 `[~]` 并写明理由，**不删除**。
4. 待办只在本文件维护；其他文档一律写「见 `devlog/待办事项.md`」，不复制清单。

## 命名约定

- 会话记录：`sessions/<YYYY-MM-DD>-phaseN-<英文短名>.md`，例如 `sessions/2026-03-05-phase1-scaffold.md`
- 文件名用英文短名，正文用中文（规避中文路径在工具链中的编码问题）。

详细的更新时机与格式要求见 [`../docs/文档维护规范.md`](../docs/文档维护规范.md)。
