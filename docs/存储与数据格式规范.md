# 存储与数据格式规范

> 本文件是数据格式、目录布局、写入与恢复策略的唯一真源。
> **改数据格式前必读**：任何字段增删都必须同步更新本文件并说明向后兼容策略。

---

## 1. 数据目录

| 项 | 值 |
|---|---|
| 根目录 | `app.getPath('userData')`，即 `%APPDATA%\ClipHistory` |
| 为何用此位置 | 路径为 ASCII，规避中文编码风险；不污染安装目录与项目仓库；卸载/备份边界清晰 |
| 目录名来源 | `package.json` 的 `productName: "ClipHistory"` |

```
%APPDATA%\ClipHistory\
  index.ndjson        # 索引：每行一条 JSON（条目元数据 + 预览）
  settings.json       # 设置
  content\
    <id>.txt          # 文本全文（UTF-8，无 BOM）
  images\
    <hash>.png        # 图片本体，文件名即内容哈希
  logs\
    main.log          # 运行日志（按大小轮转）
```

**禁止**：把上述任何数据写入程序安装目录或项目仓库。

## 2. `settings.json`

```jsonc
{
  "version": 1,
  "retentionDays": 3,        // 1–365，默认 3
  "dedupWindowMs": 5000,     // 去重窗口，默认 5000
  "paused": false,           // 是否暂停记录
  "alwaysOnTop": false,      // 窗口是否置顶（FR-13a，2026-09-15 新增）
  "opacity": 1,              // 窗口透明度 0.4–1，默认 1（FR-13b，2026-09-15 新增）
  "windowBounds": {          // 窗口位置记忆
    "x": 100, "y": 100, "width": 420, "height": 640
  }
}
```

**已删除字段**：`pasteMode`（2026-09-15，见需求 CH-01）。读取旧文件时该字段被忽略，不影响其它字段。

**读取纪律**：逐字段独立校验，非法值回退默认值并记录日志，**绝不因单字段非法而丢弃整个配置文件**。

| 字段 | 校验规则 | 非法时 |
|---|---|---|
| `retentionDays` | 整数且 1 ≤ v ≤ 365 | 回退 3 |
| `dedupWindowMs` | 整数且 0 ≤ v ≤ 60000 | 回退 5000 |
| `paused` | 布尔 | 回退 `false` |
| `alwaysOnTop` | 布尔 | 回退 `false` |
| `opacity` | 有限数字且 0.4 ≤ v ≤ 1 | 回退 1 |
| `windowBounds` | 四字段均为有限数字，且宽高为正 | 整块回退默认 |

**写入纪律**：先写同目录临时文件（`settings.json.tmp`），`fsync` 后原子替换，避免写入中途崩溃导致文件半截。

## 3. `index.ndjson`

- 格式：**每行一个 JSON 对象**，行之间以 `\n` 分隔；文件末尾必须有换行。
- 语义：**追加式日志**。同一 `id` 可多次出现，**后出现的行覆盖先前的行**（读取时按顺序折叠）。
- 优点：追加写入为 O(1)，崩溃时最多丢最后一行，不影响已有数据。

### 3.1 行结构

```jsonc
{
  "id": "1756192800000-a1b2c3d4",   // 时间戳 + 随机后缀，全局唯一且稳定
  "kind": "text",                    // "text" | "image"
  "hash": "9f86d081...",             // 内容哈希（算法见 §4）
  "createdAt": 1756192800000,        // 首次记录时间（ms，epoch）
  "updatedAt": 1756192800000,        // 最近一次复制该内容的时间（ms）；置顶/刷新会更新
  "pinned": false,                   // 是否置顶
  "textPreview": "前 120 字符...",    // 仅 text：用于列表渲染
  "image": {                         // 仅 image
    "file": "images/9f86d081....png",
    "width": 1920,
    "height": 1080,
    "sizeBytes": 284517
  }
}
```

`textPreview` 由全文派生（前 120 字符 + 省略标记），**不是**真源；真源是 `content/<id>.txt`。

### 3.2 读取与折叠

1. 逐行 `JSON.parse`，**单行解析失败则跳过该行并记录 warning**，继续处理后续行。
2. 用 `Map<id, Row>` 按出现顺序折叠，后写覆盖前写。
3. 校验必需字段（`id`、`kind`、`createdAt`、`updatedAt`）；缺失或类型错误的行跳过并记录。
4. 排序：**`updatedAt` 降序**（前端再按需分页/懒加载）。

### 3.3 压缩（Compaction）

| 触发条件 | 说明 |
|---|---|
| 行数 > 条目数 × 2 且总行数 > 2000 | 追加导致的冗余达到阈值 |
| 删除 / 清空 / 清理执行后 | 破坏性操作后立即整理 |

压缩流程：读取折叠 → 写入 `index.ndjson.tmp` → `fsync` → 原子替换 → 校验条目数与压缩前一致。压缩中途崩溃时保留原文件。

## 4. 内容哈希

| 类型 | 算法 | 输入 |
|---|---|---|
| 文本 | SHA-256 | 规范化后的 UTF-8 字节（去除 BOM，统一 `\r\n` → `\n`） |
| 图片 | SHA-256 | **原始 PNG 字节**（不是位图数组） |

用途：去重判定、图片文件命名、图片跨条目复用。

## 5. 文本全文（`content/<id>.txt`）

- 编码：UTF-8，**无 BOM**。
- 换行：统一存 `\n`（读取时按需转回当前平台换行）。
- 上限：10 万字符。超出时截断存储，并在条目上标记 `truncated: true`，界面显示「内容过长，已截断」。
- 不写入：空串、纯空白、仅换行（这些在采集阶段即被丢弃）。

## 6. 图片本体（`images/<hash>.png`）

- 命名：`<SHA-256>.png`。相同内容天然同名，**多条目共享同一文件**。
- 格式：统一 PNG（剪贴板位图无独立格式信息）。
- 元数据：宽高与字节数记录在索引中，列表渲染不读图片本体；缩略图按需加载。

## 7. 保留与回收策略

| 规则 | 内容 |
|---|---|
| 过期判定 | `pinned === false` 且 `now - updatedAt > retentionDays × 86400000` |
| 置顶豁免 | `pinned === true` 的条目**永不**被自动清理，无论期限多短 |
| 执行时机 | 应用启动时、每 6 小时、设置变更后立即执行 |
| 孤儿图片 | 清理/删除后，任何不再被索引引用的 `images/*.png` 被删除 |
| 文本全文 | 条目被删除时同步删除其 `content/<id>.txt` |
| 条目上限 | 超过 10000 条时，按「最旧的未置顶条目」优先收缩；若全为置顶则停止收缩并记录 warning |

**安全要求**：清理与孤儿回收在执行前必须先完成一次索引压缩，确保折叠后的索引是判定依据，避免误删仍被引用的图片。

## 8. 崩溃与异常恢复

| 场景 | 恢复方式 |
|---|---|
| `index.ndjson` 某行损坏 | 跳过该行，其余数据完整可用 |
| `index.ndjson` 末尾半行（写入中断） | 解析失败即跳过；下次写入前截断到最后一个完整换行 |
| 图片文件缺失或损坏 | 卡片显示占位图与「图片已丢失」标记，条目本身保留，允许手动删除 |
| `content/<id>.txt` 缺失 | 卡片显示预览文本并标注「全文已丢失」 |
| `settings.json` 损坏或部分字段非法 | 逐字段回退默认值，保留其余合法字段 |
| 压缩中途崩溃 | 原 `index.ndjson` 未被替换，数据完好 |

## 9. 版本与兼容

- `settings.json` 带 `version` 字段（当前 `1`）。
- `index.ndjson` 的兼容策略：**只增不删字段**；新增字段一律可选，读取时缺失按默认值处理。
- 若未来需要不兼容变更：另存新文件并写迁移脚本，**不原地破坏旧数据**。
- 迁移脚本必须先在临时目录验证，并保留旧文件备份。
