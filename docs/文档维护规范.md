# 文档维护规范

> 本文件规定文档与开发日志**何时更新、怎么更新**。**每阶段收尾时必读。**

## 2. 唯一真源原则

**同一事实只在一处定义，其他位置只引用、不复制。**

- 期限默认值、上限常量 → 定义在 [`存储与数据格式规范.md`](存储与数据格式规范.md) 与 `src/shared/constants.ts`，其他文档引用。
- 颜色与尺寸 → 只在 [`设计规范.md`](设计规范.md) 定义。
- IPC 通道 → 只在 [`技术方案.md`](技术方案.md) §5 与 `src/shared/constants.ts` 定义。
- 待办事项 → 只在 [`../devlog/待办事项.md`](../devlog/待办事项.md) 维护；其他文档里**不写**待办清单，只写 `见 devlog/待办事项.md`。

发现两处描述冲突时：**先判断哪处是真源，改真源，再把另一处改成引用**，并在会话记录里说明。

## 3. 每阶段收尾的固定五步

1. **验证**：`npm run typecheck` 与 `npm test` 全绿；手动验收项按 [`测试与验收标准.md`](测试与验收标准.md) 执行并记录结果。
2. **写会话记录**：新建 `devlog/sessions/<YYYY-MM-DD>-phaseN-<slug>.md`，按模板填写。**一个阶段一条，不合并。**
3. **更新索引与待办**：改 `devlog/开发索引.md` 的阶段状态；在 `devlog/待办事项.md` 勾掉完成项、补入本阶段新暴露的待办。
4. **同步标准文件**：本阶段若改动了数据格式/UI/命令/契约，回写对应标准文件，并追加其「修订记录」一行。
5. **提交**：`git add -A` + 提交，信息格式 `docs(phaseN): ...` 或 `feat(phaseN): ...`。

> 五步未完成，**不得**开始下一阶段。

## 4. 开发日志编写契约

### 4.1 何时写

| 时机 | 写什么 |
|---|---|
| 阶段完成 | 一条会话记录 + 更新索引 + 更新待办 |
| 阶段受阻 | 一条会话记录，说明阻塞点、已试过的方案、需要的决策 |
| 中途发现重要问题 | 追加到 `待办事项.md`，**不必**单独写会话记录 |
| 日常零碎改动 | **不写**。日志只记阶段级节点，避免流水账淹没重点 |

### 4.2 会话记录格式

使用 [`../devlog/sessions/_模板.md`](../devlog/sessions/_模板.md)，必含六节：

1. **本阶段目标** —— 一句话
2. **完成事项** —— 逐条列，每条带验证方式
3. **验证结果** —— 命令与结果（通过/失败），失败必须附原因
4. **问题与解决** —— 遇到什么、怎么解决；未解决的写入待办
5. **对标准文件的改动** —— 列出改了哪份、改了什么
6. **下一阶段入口** —— 下一步从哪开始，有什么前置条件

### 4.3 待办事项格式

```markdown
- [ ] **P3-01** 采集逻辑支持注入时钟 | 阶段：Phase 3 | 来源：会话记录 2026-XX-XX | 说明：为保证去重窗口可测
- [x] **P2-03** store 损坏行容错 | 阶段：Phase 2 | 完成：2026-XX-XX
```

编号规则：`P<阶段号>-<两位序号>`。**编号一经分配不复用。**

仅允许三类条目：待做 `[ ]`、完成 `[x]`、已放弃 `[~]`（须附放弃理由）。放弃的条目**不删除**，保留以留痕。

## 5. 文档写作规范

- 语言：**中文**。文件名用英文/拼音无关的通用短名，避免中文路径在工具链中的编码问题。
- 结构：每份文档开头一段「本文件是什么的唯一真源」；结尾必须有「修订记录」表。
- 表格优先：能表格化的规则一律表格化，便于逐条核对。
- 代码块标注语言（`ts`/`css`/`jsonc`/`powershell`）。
- 交叉引用用相对路径链接；新增文件后**必须**在 `CLAUDE.md` 索引中登记。
- 不使用「大概」「可能」「尽量」等模糊措辞描述必须遵守的规则；不确定的事就标为「待确认」并写入待办。
- 不复制粘贴实现细节代码到文档（易失效）；文档只写契约、格式与规则。

## 6. 文档与代码一致性检查

每个阶段收尾顺手确认：

- [ ] `CLAUDE.md` 索引里的每个路径**真实存在**（失效链接必须修）。
- [ ] `package.json` 的脚本与 [`构建与运行.md`](构建与运行.md) §3 一致。
- [ ] `src/shared/constants.ts` 的常量与 [`存储与数据格式规范.md`](存储与数据格式规范.md) 一致。
- [ ] IPC 通道变更已同步 [`技术方案.md`](技术方案.md) §5。
- [ ] 新增的数据字段已同步存储规范，且说明了向后兼容策略。
