## 2. 安装

### 2.1 受限环境下的安装（本机已实测遇到）

在**文件沙箱只允许写工作区**的环境中，直接 `npm install` 会连续撞上两道系统级限制。以下步骤可绕过，且**不需要放宽任何权限**：

| 症状 | 原因 | 对策 |
|---|---|---|
| `EPERM: operation not permitted, open '...\_cacache\tmp\...'` | npm 缓存默认位于 `%LOCALAPPDATA%\npm-cache`，在工作区之外 | 用 `--cache` 把缓存指到可写目录（如 `%TEMP%`） |
| `EPERM: spawn`（`arborist/lib/arborist/rebuild.js` 抛出） | 依赖的 postinstall 需要派生进程，被沙箱禁止 | 加 `--ignore-scripts` |

完整命令：

```powershell
$cache  = Join-Path $env:TEMP "cliphistory-npm-cache"
$ecache = Join-Path $env:TEMP "cliphistory-electron-cache"
New-Item -ItemType Directory -Force -Path $cache, $ecache | Out-Null
$env:ELECTRON_CACHE = $ecache
npm install --cache "$cache" --ignore-scripts
```

`--ignore-scripts` 会跳过 Electron 自身的 postinstall，还需**手动补一步**下载 Electron 二进制。注意 `@electron/get` 默认还想写 `%LOCALAPPDATA%\electron`，必须用 **`electron_config_cache`**（新的变量名）重定向：

```powershell
$env:electron_config_cache = Join-Path $env:TEMP "cliphistory-electron-cache"
node node_modules/electron/install.js
# 校验
Test-Path node_modules/electron/dist/electron.exe   # 应为 True
```

> `--ignore-scripts` 会跳过**所有**依赖的 postinstall（含 `electron-builder` 依赖链里的 `electron-winstaller`）。若 Phase 7 打包报缺件，见 §2.3。

### 2.2 为什么构建不用 Vite（Phase 1 实测结论）

本机文件沙箱**禁止 Node 派生任何子进程**（`child_process` 报 `EPERM`），而 Vite 8 的 rolldown/esbuild 原生工具链必须派生进程才能工作：

```
✗ npx vite build
  EPERM: spawn  ← vite/dist/node/chunks/node.js → execFile → spawn
```

因此渲染层改为**用 tsc 直接编译**（tsc 是纯 JS，在进程内完成编译，不需派生）。配套的自写脚本承担 Vite 原本的两件事：

| 原本由 Vite 负责 | 现在由谁负责 |
|---|---|
| 渲染层 TS → JS | `tsc -p tsconfig.renderer-build.json` |
| 打包 / 代码分割 | 不需要：本应用渲染层只有少量文件，输出原生 ESM 由 Electron 直接加载 |
| 搬运 html / css / 资源 | [`../scripts/copy-static.mjs`](../scripts/copy-static.mjs) |
| preload 打包 | [`../scripts/build-preload.mjs`](../scripts/build-preload.mjs)（见 §2.2.1） |
| 开发热更新 | 暂不提供；改渲染层后重新 `npm run dev`（本应用构建约 1 秒） |

**引入任何 esbuild / rollup / swc 类工具前都要先验证它能否在本机运行**，否则会在构建期直接失败。

#### 2.2.1 preload 必须打包成自包含单文件（C-01）

`sandbox: true` 下的 preload **不能 `require` 相对模块**，实测报：

```
Error: module not found: ../shared/constants
```

因此 `scripts/build-preload.mjs` 先用 tsc 编译为 CommonJS，再把共享常量字面量**内联**进产物，使 `dist/preload/preload.js` 只依赖 electron 内置模块。该脚本在内联失败或产物仍含相对 `require` 时**直接报错**，不会静默产出会崩的 preload。

### 2.3 Electron 与打包在本机的运行限制（重要）

| 事项 | 实测结果 | 影响与对策 |
|---|---|---|
| `electron --version` | ✅ 成功 | 取版本号等不启动 Chromium 的操作正常 |
| **启动应用窗口** | ❌ 在默认沙箱下崩溃（退出码 `0x7003`，仅报 `crashpad ... not connected`，无任何 JS 日志） | Chromium 的进程模型与 crashpad 需要命名管道，被沙箱阻断。**必须放宽到 `danger-full-access` 才能运行**；最小 Electron 探针同样崩溃，证明与项目代码无关 |
| 放宽后启动 | ✅ 通过（`--smoke` 自检返回 0） | 见 §4 冒烟自检 |
| electron-builder 打包 | ⚠️ **打包动作可用，但必须联网下载 Electron 发行版** | 实测能走到 `packaging` 阶段（说明**进程派生不是障碍**），随后失败于 `connect ETIMEDOUT 20.205.243.166:443` —— 它要从 GitHub 拉约 367MB 的 Electron 发行版，而本机 `github.com` **不可达**。**结论：本机无法用 electron-builder 出安装包**，改走手工组装免安装目录（见 §7） |

**结论**：日常开发与验收需要在能运行 Chromium 的环境下执行 `npm run dev`；自动化验证可用 `npm run smoke`；交付物用 `npm run dist`（手工组装，零网络）。

### 2.4 单元测试的运行方式（Phase 2 起）

测试入口是 [`../test/run-tests.mjs`](../test/run-tests.mjs)，它做两件事：

1. 用 `node:module` 的 **`registerHooks`**（同步钩子 API，Node ≥ 24）注册模块解析钩子，把源码里的
   **无扩展名导入**（如 `../shared/constants`）与 **`.js` 后缀导入**映射到磁盘上真实的 `.ts` 文件；
2. 在同**一个进程内**依次 `import()` 所有 `test/*.test.ts`。

```powershell
npm test          # 等价于 node test/run-tests.mjs
```

#### 为什么不用 `node --test`

一共撞了三堵墙，逐条都是实测结论：

| 问题 | 实测症状 | 说明 |
|---|---|---|
| 默认按文件派生进程做隔离 | `Error: spawn EPERM`（`node:internal/test_runner/runner`） | 本机文件沙箱禁止 Node 派生任何子进程 |
| 加 `--experimental-test-isolation=none` 后 | 测试能跑，但导入解析失败 | 该内部运行上下文**不应用**通过 `--import` 注册的解析钩子 |
| ESM 要求显式扩展名 | 无扩展名 → `Cannot find module '.../src/main/store'`；写 `.js` → `Cannot find module '.../content.js'` | 源码为能被 tsc 编译成 CommonJS 而使用无扩展名导入；Node 的 ESM 解析既不会补 `.ts`，也不会把 `.js` 映射到 `.ts` |

结论：自己写入口，用一个同步解析钩子把两边对接起来。**好处是零构建步骤、零测试框架依赖** ——
Node 24 的原生类型擦除直接执行 `.ts`。

> 关键坑：**异步的 `resolve` 导出（`--loader` / `--import` 那种写法）在本机 Node 24 下不会被调用**，
> 模块解析仍走默认逻辑而失败。必须用 `registerHooks`。本文件最初写的方案就是踩了这个坑之后才改对的。

#### 必须遵守的代价

同进程运行意味着测试之间**没有进程级隔离**，一个用例污染全局状态会影响后续用例。
因此每个用例必须自建并清理自己的临时数据目录，绝不共用可变状态 —— 这与
[`测试与验收标准.md`](测试与验收标准.md) §3 的既有要求一致，在该约束下不构成问题。
[`../test/helpers/paths.ts`](../test/helpers/paths.ts) 提供 `createTestStore()`（含可注入时钟）与
`dispose()`，内部强制使用 `os.tmpdir()`，从机制上防止误写真实数据目录。

> 关于 `MODULE_TYPELESS_PACKAGE_JSON` 警告：Node 运行 `.ts` 时会提示未声明模块类型。
> 本项目 `package.json` 必须保持 CommonJS（主进程由 tsc 编译为 CommonJS），**不要**加
> `"type": "module"`，否则会破坏主进程。测试文件用 ESM 语法会被自动识别为 ESM，警告可忽略。

## 4. 冒烟自检（无法肉眼看窗口时用这个）

`npm run smoke` 会完成两级验证，全部通过才返回退出码 0：

**第一级：窗口与通路**

1. 主进程创建窗口并加载渲染层；
2. 等 `did-finish-load` 后，在渲染层里调用 `window.clipHistory.ping()`；
3. 通过则打印健康串（存储/采集/清理/托盘状态），失败则退出码 1。

**第二级：集成自检（`src/main/smoke.ts`）**

在**无界面点击**的情况下，用采集器的测试接缝注入一条文本与一条图片，
然后调用与界面**完全相同**的 IPC 处理器走一遍完整流程：

采集落库 → 列表 → 搜索（中/英文）→ 类型筛选 → 置顶 → 取详情 → 复制到剪贴板
→ 删除 → 撤销 → 设置读写（含越界回退）→ 5 项非法入参拒绝 → 诊断 → 清空（保留置顶）

共 34 项断言。任一项失败即打印明细并返回退出码 1。

**数据隔离**：自检会写入数据，因此 `scripts/run-electron.mjs --smoke` 会把
`CLIPHISTORY_DATA_DIR` 指向 `os.tmpdir()` 下的临时目录 —— **绝不触碰** `%APPDATA%\ClipHistory`。

**它验证什么**：主进程能启动、窗口能创建、渲染层能加载、preload 白名单真的注入成功、
IPC 处理器能正确读写真实 store、非法入参被拒绝、错误提示可行动。
**它不验证什么**：界面长什么样、布局与交互是否符合 [`设计规范.md`](设计规范.md)，
以及真实剪贴板行为（那是 §5.1.1 的人工清单）。

## 5. 构建产物

| 路径 | 内容 | 是否入库 |
|---|---|---|
| `dist/main/` | 主进程编译结果 | ❌ 忽略 |
| `dist/shared/` | 共享模块（主进程用） | ❌ 忽略 |
| `dist/preload/preload.js` | 自包含的 preload 单文件 | ❌ 忽略 |
| `dist/renderer/renderer/` | 渲染层：`index.html`、`main.js`、`styles.css`、`assets/` | ❌ 忽略 |
| `dist/renderer/shared/` | 共享模块（渲染层用，浏览器侧） | ❌ 忽略 |
| `dist/preload-tmp/` | preload 打包的临时目录，构建后自动删除 | ❌ 忽略 |
| `release/` | 安装包与免安装 exe（Phase 7） | ❌ 忽略 |
| `node_modules/` | 依赖 | ❌ 忽略 |

**渲染层产物路径为何是 `dist/renderer/renderer/`**：`tsconfig.renderer-build.json` 的 `rootDir=src` 与 `outDir=dist/renderer` 决定了 `src/renderer/index.html` 对应 `dist/renderer/renderer/index.html`。主进程的加载路径必须与此一致（见 [`技术方案.md`](技术方案.md) C-02）。

**用户数据不在此列**：历史数据位于 `%APPDATA%\ClipHistory`，与构建产物无关，见 [`存储与数据格式规范.md`](存储与数据格式规范.md) §1。

## 6. 开发模式说明

- `npm run dev` 会构建并启动 Electron，数据写入真实的 `%APPDATA%\ClipHistory`。
- **调试期间想用独立数据**：启动前设置环境变量 `CLIPHISTORY_DATA_DIR` 指向临时目录（Phase 2 实现该开关），避免测试数据污染日常历史。
- 渲染层调试：`Ctrl+Shift+I` 打开开发者工具（仅开发模式）。
- 环境变量一览：

| 变量 | 作用 |
|---|---|
| `CLIPHISTORY_DEV_SERVER` | 设置后加载该 URL 而非本地文件（供将来接热更新用） |
| `CLIPHISTORY_SMOKE_TEST` | 冒烟自检开关，由 `npm run smoke` 自动设置 |
| `CLIPHISTORY_DATA_DIR` | 覆盖数据目录（Phase 2） |

## 7. 打包流程

1. 确认 `npm run typecheck` 与 `npm test` 通过。
2. 运行 `npm run build`（编译主进程、打包 preload、编译渲染层、搬运静态资源）。
3. 运行 `npm run dist` —— 等价于「build + 组装免安装包」，**全程不需要网络**。
4. 产物在 `release/ClipHistory-win-x64/`：
   - `ClipHistory.exe` —— 双击即可运行
   - `resources/app/` —— 应用代码
   - `resources/assets/` —— 托盘图标（`app.isPackaged` 时从这里读）
5. 验收：把该目录**复制到干净位置**运行，确认能启动、托盘出现、复制内容被记录、数据写在 `%APPDATA%\ClipHistory` 而非程序所在目录。

### 7.1 为什么没有 NSIS 安装包（重要）

原计划用 electron-builder 出安装包 + 免安装 exe，**实测本机做不到**：
electron-builder 的打包动作本身可用（能走到 `packaging` 阶段），但它**必须从 GitHub 下载 Electron 发行版**（约 367MB），
而本机 `github.com` 不可达（`connect ETIMEDOUT`）。详见 §2.3 与 [`技术方案.md`](技术方案.md) C-19。

因此交付走 **手工组装**（[`../scripts/build-portable.mjs`](../scripts/build-portable.mjs)）：直接复用 `npm install` 时已下载的
`node_modules/electron/dist`，把它复制成产物目录、把 `electron.exe` 改名为 `ClipHistory.exe`、
再放置 `resources/app`（应用代码）与 `resources/assets`（图标）。

| 这样做的代价 | 说明 |
|---|---|
| 没有开始菜单项与卸载程序 | 免安装目录，删目录即卸载 |
| 整包约 368MB | Electron 运行时本身就有 367MB，属正常量级 |
| 首次运行可能触发杀软提示 | 未签名的可执行文件，Windows SmartScreen 可能拦一次 |

**若将来网络可达或想做成安装包**：安装 `electron-builder` 所需的 NSIS 工具链并允许它联网下载发行版即可，
应用代码无需改动（组装脚本与 builder 产出的目录布局一致，也是 Electron 的标准布局）。

### 打包注意（Electron 常见坑）

| 坑 | 处理 |
|---|---|
| **打包资源路径必须与代码约定一致** | `app.isPackaged` 时 `resolveAssetsDir()` 读 `process.resourcesPath/assets`，所以 `assets/` 要放在 `resources/assets`；同时应用文件要放 `resources/app`（见 C-20） |
| **Electron 自带的示例应用会冲突** | 必须删掉 `resources/default_app.asar`（组装脚本已处理） |
| 中文目录名 | 产物输出到 `release/`（ASCII 路径），避免个别工具链的编码问题 |
| 运行时路径 | **绝不**依赖 `process.cwd()`，一律用 `app.getPath()` / `__dirname` / `process.resourcesPath` |
| 可执行文件图标 | Windows 需要 `.ico`（已由 `npm run gen:icons` 生成）；组装方式不写 exe 图标，如需写图标要另用资源编辑工具 |

## 8. 分发给他人的实测结论

`release/ClipHistory-win-x64/` 就是**软件本体**：Electron 运行时 + 应用代码全在这个目录里（共 119 个文件），
不含 `node_modules`，不需要安装任何东西。压缩后发给别人，对方解压双击 `ClipHistory.exe` 即可用。

| 项 | 实测值 / 结论 | 验证方式 |
|---|---|---|
| 未压缩体积 | **367.7 MB**（`ClipHistory.exe` 自身 240 MB，Chromium 在里面） | `npm run dist` 输出 |
| 压缩后体积 | **150.9 MB（41%）** | `Compress-Archive -CompressionLevel Optimal` |
| 位置无关性 | 复制到**含中文与空格**的其它路径后启动 → 退出码 0，**64/64 自检通过** | 复制到 `%TEMP%\历史粘贴 便携测试\` 运行打包 exe |
| 外部运行库依赖 | **无**：逐个扫描 exe 与全部 dll，对 `vcruntime140` / `msvcp140` / `ucrtbase` 的动态引用均为零 | 二进制字节扫描 |
| 系统要求 | **Windows 10 / 11（64 位）** | Electron 44 已移除 32 位（[breaking changes](https://www.electronjs.org/docs/latest/breaking-changes)）；Windows 7/8/8.1 自 Electron 23 起不再支持（[Electron 23 公告](https://www.electronjs.org/blog/electron-23-0)） |
| 管理员权限 | 不需要；数据写在对方自己的 `%APPDATA%\ClipHistory` | — |
| 对方的历史记录 | 从空开始，**不会带过去**你的记录 | 数据目录按用户隔离 |

**必须提前告知对方的两件事**：

1. **SmartScreen 警告**：可执行文件未签名，从网络传来的包首次运行可能显示「Windows 已保护你的电脑」，
   需点「更多信息 → 仍要运行」；部分杀毒软件也可能误报。
2. **压缩包再发送**：不少聊天工具会拦截裸 `.exe`，压成 zip 正好能过（这也是推荐的分发方式）。

**已知缺陷**：`ClipHistory.exe` 未写入应用图标，对方看到的是 Electron 默认图标（见 `devlog/待办事项.md` P7-05）。

**再次压缩时注意**：若应用正在运行，`release/` 里的 `.pak` / `icudtl.dat` 等文件被占用，压缩会失败
（实测报 `The process cannot access the file ... because it is being used by another process`）。先退出应用再压缩。

## 9. 依赖管理

- 运行时依赖只有 `electron`；其余为 `devDependencies`。
- 添加依赖后必须：更新 `package-lock.json`、在 [`技术方案.md`](技术方案.md) §2.1 记录用途与版本。
- 依赖升级单独一次提交，不与功能改动混在一起。
- **TypeScript 7 注意事项**：`moduleResolution: "node10"` / `"Node"` 已被移除，使用 CommonJS 时**省略** `moduleResolution` 选项，否则报 `TS5108`。

## 10. 常见问题排查

| 症状 | 排查方向 |
|---|---|
| `npm install` 报 `EPERM ... _cacache` | 用 `--cache` 指向可写目录（§2.1） |
| `npm install` 报 `EPERM: spawn` | 加 `--ignore-scripts`（§2.1） |
| `node node_modules/electron/install.js` 报 `EPERM mkdir ...\AppData\Local\electron` | 设置 `electron_config_cache` 重定向（§2.1） |
| `node_modules/electron/dist/electron.exe` 不存在 | Electron 二进制未下载，跑 §2.1 的手动步骤 |
| 应用启动即崩溃、退出码 `0x7003`、只有 crashpad 报错 | 沙箱阻断 Chromium，需放宽权限运行（§2.3） |
| `Unable to load preload script` + `module not found: ../shared/...` | preload 没打包成自包含单文件（§2.2.1） |
| `冒烟自检失败：渲染层加载失败（-6 ERR_FILE_NOT_FOUND）` | 主进程加载路径与产物路径不一致（C-02 / 见 §5） |
| `tsc` 报 `TS5108 Option 'moduleResolution=node10' has been removed` | 删掉 `moduleResolution` 配置项（§8） |
| `npm test` 报 `EPERM: spawn`（`node:internal/test_runner/runner`） | `node --test` 默认为每个测试文件派生进程。改用 `npm test`（自定义同进程入口），见 §2.4 |
| `npm test` 报 `Cannot find module '.../src/main/store'` 或 `.../content.js` | ESM 需要显式扩展名，而源码用无扩展名导入。自定义入口的解析钩子已处理，见 §2.4 |
| `tsc -p tsconfig.test.json` 报测试里传了非法枚举 | 有意为之的「不可信入参」用例需要显式类型断言，见 [编码规范](编码规范.md) §2 |
| 渲染层报 `require is not defined` | 误在渲染层用 Node API；应改为经 preload 走 IPC |
| 界面一直停在「正在加载…」，日志无报错 | 渲染层的模块**没执行**（浏览器 ESM 加载失败是静默的）。两个已知原因：① 渲染层 import 了共享模块（见 `技术方案.md` C-07）；② preload 打包漏内联常量导致 `XXX is not defined`（见 C-08）。用 `npm run smoke` 的界面就绪断言直接定位 |
| `npm run smoke` 报 `IPC_EVENT is not defined` | preload 打包漏内联常量，见 C-08；检查 `scripts/build-preload.mjs` 的 `INLINEABLE_CONSTANTS` |
| 应用启动后立刻退出、无任何日志 | 可能有旧的 Electron 实例占着单实例锁。检查并结束残留进程：`Get-Process -Name electron \| Stop-Process -Force`。自检模式已改为跳过该锁（见 `技术方案.md` C-11） |
| 弹窗/面板点了关闭但关不掉 | 作者样式给元素写了 `display`，压掉了 `hidden`（见 `技术方案.md` C-10）。检查 `styles.css` 是否有 `[hidden] { display: none !important; }` |
| 构建「看起来失败」但产物正常 | 很可能是 PowerShell 管道吞掉了退出码（见 C-09）。用 `node scripts/build-all.mjs > $null 2>&1; $LASTEXITCODE` 复核 |
| 托盘图标不显示 | 图标路径是否用了相对 `process.cwd()`；资源是否被打包 |
| 复制的内容不进历史 | 是否处于暂停状态；忽略规则是否过滤；序列号判定是否误判为自触发 |
| 打包后启动白屏 | 渲染层资源路径是否用了绝对/`file://` 错误基址；是否被 `files` 规则漏掉 |
| 中文乱码 | 文件读写是否统一 UTF-8；文本是否残留 BOM |
| 压缩 `release/` 时部分文件报「正在被另一个进程使用」 | 应用正在运行，`.pak`/`icudtl.dat` 等被占用。先退出应用再压缩（见 §8） |
| 别人拿到压缩包首次运行被 SmartScreen 拦住 | 未签名的可执行文件属预期行为，见 §8 的提示话术 |
