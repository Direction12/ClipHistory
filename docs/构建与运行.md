# 构建与运行

> 本文件是环境要求、命令与打包流程的唯一真源。**环境或构建报错时先读本文件。**

---

## 1. 环境要求

| 项 | 要求 | 本机实测 |
|---|---|---|
| 操作系统 | Windows 10 / 11 | Windows |
| Node.js | ≥ 20（建议 22 或 24） | **v24.21.0** ✅ |
| npm | ≥ 10 | **11.19.0** ✅ |
| Git | ≥ 2.40 | **2.55.0.windows.5** ✅ |
| MSVC 生成工具 | **不需要** | 未安装 ✅（Electron 预编译，无需本机编译） |
| Rust | **不需要** | 未安装 ✅（已放弃 Tauri 方案） |

> 若将来有人提议 Tauri 或需要本机原生编译模块，必须先在 [`技术方案.md`](技术方案.md) 说明并确认工具链安装成本。

## 2. 首次安装

```powershell
cd "C:\Users\Direction\Desktop\历史粘贴"
npm install
```

安装后应生成 `package-lock.json`，且 `node_modules/` 被 `.gitignore` 忽略。

## 3. 常用命令

| 命令 | 作用 | 说明 |
|---|---|---|
| `npm run typecheck` | 类型检查（不产出文件） | 每次提交前必跑 |
| `npm test` | 运行 `test/` 下单元测试 | 纯逻辑测试，**不需要启动 Electron** |
| `npm run dev` | 开发模式启动应用 | 主进程 + 渲染层；改渲染层可热更新 |
| `npm run build` | 产出构建结果到 `dist/` | 打包前必跑 |
| `npm run dist` | 用 electron-builder 打 Windows 安装包 + 免安装 exe | 输出到 `release/` |

> 命令在 Phase 1 落地到 `package.json`；本文件与该文件必须保持一致。

## 4. 构建产物

| 路径 | 内容 | 是否入库 |
|---|---|---|
| `dist/` | 构建中间产物与主进程编译结果 | ❌ 忽略 |
| `dist-electron/` | 主进程/preload 编译输出（若采用） | ❌ 忽略 |
| `release/` | 安装包与免安装 exe | ❌ 忽略 |
| `node_modules/` | 依赖 | ❌ 忽略 |

**用户数据不在此列**：历史数据位于 `%APPDATA%\ClipHistory`，与构建产物无关，见 [`存储与数据格式规范.md`](存储与数据格式规范.md) §1。

## 5. 开发模式说明

- `npm run dev` 会启动 Electron 主进程并加载渲染层。数据写入真实的 `%APPDATA%\ClipHistory`。
- **调试期间想用独立数据**：可在启动前设置环境变量 `CLIPHISTORY_DATA_DIR` 指向临时目录（Phase 2 实现该覆盖开关），避免测试数据污染日常历史。
- 渲染层调试：`Ctrl+Shift+I` 打开开发者工具（仅开发模式）。
- 主进程日志：控制台输出 + `%APPDATA%\ClipHistory\logs\main.log`。

## 6. 打包流程

1. 确认 `npm run typecheck` 与 `npm test` 通过。
2. 运行 `npm run build`。
3. 运行 `npm run dist`。
4. 产物在 `release/`：
   - `ClipHistory Setup <版本>.exe` —— NSIS 安装包
   - `ClipHistory <版本>.exe` —— 免安装（portable）
5. 验收：把产物**复制到干净目录**运行，确认：能启动、托盘出现、复制内容被记录、数据写在 `%APPDATA%\ClipHistory` 而非程序所在目录。

### 打包注意（Electron 常见坑）

| 坑 | 处理 |
|---|---|
| 中文目录名 | 构建产物输出路径建议不含中文（可在 `dist`/`release` 配置里指向英文临时目录），避免个别工具链编码问题 |
| 资源未打包 | 托盘图标等资源必须在 builder 配置的 `files`/`extraResources` 中显式包含 |
| 图标缺失 | `assets/` 下图标需提供 `.ico`（Windows）用于安装包与 exe |
| 杀软误报 | 免安装单文件 exe 易误报；优先提供 NSIS 安装包 |
| 路径混淆 | 运行时**绝不**依赖 `process.cwd()`，一律用 `app.getPath()` / `__dirname` |

## 7. 依赖管理

- 运行时依赖只有 `electron`；其余为 `devDependencies`。
- 添加依赖后必须：更新 `package-lock.json`、在 [`技术方案.md`](技术方案.md) 记录用途与理由。
- 依赖升级单独一次提交，不与功能改动混在一起。

## 8. 常见问题排查

| 症状 | 排查方向 |
|---|---|
| `npm run dev` 无窗口 | 主进程是否抛错；`main` 字段路径是否正确；preload 路径是否拼对 |
| 渲染层报 `require is not defined` | 误在渲染层用 Node API；应改为经 preload 走 IPC |
| 托盘图标不显示 | 图标路径是否用了相对 `process.cwd()`；资源是否被打包 |
| 复制的内容不进历史 | 是否处于暂停状态；忽略规则是否过滤；序列号判定是否误判为自触发 |
| 打包后启动白屏 | 渲染层资源路径是否用了绝对/`file://` 错误基址；是否被 `files` 规则漏掉 |
| 中文乱码 | 文件读写是否统一 UTF-8；文本是否残留 BOM |
