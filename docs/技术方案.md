# 技术方案

> 本文件是本项目技术栈、模块职责与接口契约的唯一真源。
> 动代码结构、引入新依赖之前，必须先读本文件并同步更新它。

---

## 1. 技术选型与依据

| 项 | 选择 | 依据 |
|---|---|---|
| 运行时 | **Electron** | 本机已具备 Node v24.21.0 / npm 11.19.0 / pnpm 12.4.1；**无 rustc/cargo、无 MSVC 生成工具**，故 Tauri 需额外安装重型工具链，不采用；**无 .NET SDK**，故 WPF/WinUI 不采用。Electron 自带剪贴板与托盘能力，开箱可用。 |
| 语言 | **TypeScript** | 类型约束数据格式与 IPC 契约，降低跨进程出错概率 |
| 构建 | **tsc（主进程 / preload / 渲染层）+ 自写脚本（preload 打包、静态资源搬运）** | **Vite 已弃用**：实测本机文件沙箱禁止 Node 派生进程，Vite 8 的 rolldown/esbuild 原生工具链报 `EPERM: spawn`，无法工作。tsc 是纯 JS、在进程内编译，可正常工作。详见 §2.1 与 [`构建与运行.md`](构建与运行.md) §2.2 |
| 渲染层框架 | **无框架**（原生 DOM + CSS + TS） | 界面规模小（单列表 + 少量弹层），引入 React/Vue 收益低、依赖多 |
| 打包 | **electron-builder** | 计划产出 NSIS 安装包 + 免安装 exe；**但本机对进程派生有限制，Phase 7 前必须先做最小可行性验证**（见 [`构建与运行.md`](构建与运行.md) §2.3） |
| 存储 | **本地文件**（NDJSON 索引 + 独立文件） | 1–5 天量级下性能足够；零原生模块，规避 better-sqlite3 的 ABI 重编译风险 |
| 运行时依赖 | **仅 electron** | 精简依赖面，安全与可维护性优先 |

### 2.2 平台约束（实测得出）

| 编号 | 约束 | 后果与对策 |
|---|---|---|
| C-01 | **sandbox 下的 preload 无法 `require` 相对模块** | 实测报 `module not found: ../shared/constants`。故 preload 必须打包成自包含单文件：`scripts/build-preload.mjs` 先用 tsc 编译为 CommonJS，再把共享常量字面量内联进去 |
| C-02 | **渲染层的编译产物路径是 `dist/renderer/renderer/index.html`** | 因为 `tsconfig.renderer-build.json` 的 `rootDir=src`、`outDir=dist/renderer`。主进程加载路径必须与此一致，不要「顺手」改成 `dist/renderer/index.html` |
| C-03 | **测试不能靠 `node --test` 跑** | 三个叠加的坑：① 默认按文件派生进程 → 沙箱 `EPERM: spawn`；② 加 `--experimental-test-isolation=none` 后，其内部上下文**不应用** `--import` 注册的解析钩子；③ ESM 要求显式扩展名，而源码为能被 tsc 编译成 CommonJS 使用无扩展名导入。对策：`test/run-tests.mjs` 用 `node:module` 的 **`registerHooks`**（同步钩子）注册解析映射，再在同进程内 import 各测试文件。**注意：异步的 `resolve` 导出在本机 Node 24 下不会被调用**。代价是测试间无进程隔离，故每个用例必须自建自清临时目录 |
| C-04 | **测试运行器需要 `package.json` 保持 CommonJS** | 不可为了消除 `MODULE_TYPELESS_PACKAGE_JSON` 警告而加 `"type": "module"` —— 那会破坏由 tsc 编译为 CommonJS 的主进程。测试文件用 ESM 语法会被自动识别，警告可忽略 |
| C-05 | **Electron 44 的剪贴板 API 已不兼容旧写法** | 运行时实测：`readText()` / `read()` / `has()` / `writeText()` 均返回 Promise；`readImage()` / `writeImage()` / `availableFormats()` **全部为 `undefined`**。任何「同步读剪贴板」或「拿图片对象」的写法都无法编译也无法运行。新用法见 D-13/D-14/D-15：按 MIME 类型取 Blob、自行解析 PNG 宽高 |
| C-06 | **`clipboard` 的类型定义不完备** | `electron.d.ts` 里 `clipboard.read()` 声明为 `Promise<ClipboardItem[]>`，但实测 `readText()` 也是异步（与类型签名的同步写法不一致）。**涉及剪贴板的结论必须以运行时实测为准，不能只信类型定义** |
| C-07 | **渲染层不能 import 共享模块（含 `src/shared/constants.ts`）** | 渲染层由浏览器以原生 ESM 加载，浏览器**不做扩展名补全、也不做目录解析**；而 tsc **不会**给无扩展名导入补 `.js`，相对路径又按源码目录（`src/renderer/`）计算，产物却在 `dist/renderer/renderer/`。更糟的是模块加载失败时**模块静默不执行**，界面永远停在 HTML 里的初始文字「正在加载…」。对策：**渲染层完全自包含**，只依赖 `src/renderer/global.d.ts` 的环境声明；共享契约由集成自检断言兜底 |
| C-08 | **preload 打包必须穷尽校验被导入的常量** | preload 是自包含打包，凡 `import` 的共享常量都必须在 `scripts/build-preload.mjs` 的 `INLINEABLE_CONSTANTS` 里登记并内联。漏登记会在运行时抛 `XXX is not defined`，而它发生在渲染层调用事件订阅时，表现为界面卡在「正在加载…」，**排查成本极高**（本项目真实踩过：漏了 `IPC_EVENT`）。现已在构建期做穷尽校验，不认识的常量直接让构建失败 |
| C-09 | **PowerShell 管道会吞掉真实退出码** | `node build.mjs \| Select-String ...` 之后读 `$LASTEXITCODE` 得到的是 **`Select-String` 的**退出码，不是 node 的。这曾导致「构建其实成功了却被误判为失败」。**验证退出码时不要接管道**：`node build.mjs > $null 2>&1; $LASTEXITCODE`。同理，Windows PowerShell 5.1 默认非 UTF-8，不要在管道里输出中文源码内容做判断 |

## 3. 进程与职责边界

| 进程 | 职责 | 绝不负责 |
|---|---|---|
| 主进程 main | 剪贴板轮询、数据读写、托盘、窗口生命周期、IPC 处理、过期清理 | 不参与 DOM 渲染 |
| 预加载 preload | 用 `contextBridge` 暴露白名单方法 | 不暴露 `ipcRenderer` 原始对象、不暴露 Node 模块 |
| 渲染层 renderer | 展示列表、搜索筛选、卡片交互、设置面板 | 不直接访问文件系统、不直接操作剪贴板 |

安全配置（固定，不得放宽）：

```ts
webPreferences: {
  contextIsolation: true,
  nodeIntegration: false,
  sandbox: true,
  preload: <path to preload.js>,
}
```

## 5. IPC 契约

通道名集中在 `src/shared/constants.ts`，**新增通道必须同步更新本节**。

### 5.1 渲染层 → 主进程（invoke，均有返回值）

| 通道 | 入参 | 返回 | 用途 |
|---|---|---|---|
| `entries:list` | `{ query?: string; kind?: 'all'\|'text'\|'image' }` | `ClipEntryMeta[]` | 取列表（含预览，不含全文） |
| `entries:get` | `{ id: string }` | `ClipEntryDetail \| null` | 取单条全文/图片路径 |
| `entries:setPinned` | `{ id: string; pinned: boolean }` | `ClipEntryMeta \| null` | 置顶/取消置顶 |
| `entries:delete` | `{ id: string }` | `boolean` | 删除单条 |
| `entries:restore` | `{ entry: ClipEntryDetail }` | `ClipEntryMeta` | 撤销删除 |
| `entries:clear` | `{ keepPinned: true }` | `{ removed: number }` | 清空（保留置顶） |
| `paste:copy` | `{ id: string }` | `OperationResult` | 仅复制到剪贴板（Phase 5 完成） |
| `paste:toActive` | `{ id: string }` | `PasteResult`＝`OperationResult & { mode; autoPasted; notice? }` | 写回并尝试自动粘贴（Phase 5 完成自动粘贴） |
| `settings:get` | — | `Settings` | 读设置 |
| `settings:update` | `SettingsSeed` | `Settings` | 改设置（含期限），返回校验后的结果 |
| `app:diagnostics` | — | `{ entries; text; image; pinned; damagedLines; paused; watcherRunning; cleanupRunning; dataRoot }` | 诊断计数与运行状态；**不含任何剪贴板内容** |

**契约纪律（Phase 4 冻结）**：

1. 所有入参在主进程侧**必须**做类型与范围校验；渲染层传参不可信（见 [`编码规范.md`](编码规范.md) §6）。
2. 所有 handler **一律以抛出异常表示失败**；主进程统一包成 `{ ok: false, error }` 返回，
   渲染层只需判断 `ok`，不必区分「抛异常」与「返回失败对象」两种风格。
3. 返回给渲染层的条目数据**只含元数据与预览**；文本全文仅在 `entries:get` 时按需取，
   避免列表加载把全部正文读进内存。
4. `entries:clear` 的 `keepPinned` 固定为 `true`：清空必须保留置顶条目（FR-15），
   不接受渲染层传入其它值。
5. `paste:copy` 的**文本**部分在 Phase 4 已可用；**图片**写回依赖 Phase 5 修订后的方案
   （Electron 44 移除了 `writeImage()`，见 C-05）。图片写回失败必须返回明确的 `error`，不得静默失败。

### 5.2 主进程 → 渲染层（send）

| 通道 | 载荷 | 用途 |
|---|---|---|
| `entries:changed` | — | 通知列表数据已变，渲染层重新拉取 |
| `watcher:state` | `{ paused: boolean }` | 暂停/恢复状态变化 |

### 5.3 返回错误的语义（渲染层据此提示用户）

| 场景 | `error` 文案要求 |
|---|---|
| 入参非法 | 说明哪个字段不合法 |
| 条目不存在 | 说明「条目可能已被删除」，并提示刷新 |
| 写剪贴板失败 | 说明失败原因；提权窗口场景要提示改为手动 Ctrl+V（LIM-01） |
| 尚未支持 | 明确写「该功能将在后续版本提供」，不得假装成功 |


## 6. 关键实现决策

| 编号 | 决策 | 理由 |
|---|---|---|
| D-01 | 剪贴板采用 800ms 轮询 | Windows/Electron 无可靠原生变更事件（见 LIM-02） |
| D-02 | 用剪贴板序列号 + 内容哈希双重判定防自触发 | 软件写回剪贴板时记录预期序列号，下一轮比对时跳过 |
| D-03 | 文本全文与索引分离存储 | 索引保持小体积，列表加载快；全文按需读取 |
| D-04 | 图片按内容哈希命名并复用文件 | 重复图片天然合并，不重复占盘 |
| D-05 | 索引用 NDJSON 追加 + 阈值压缩 | 追加为 O(1) 写入；压缩仅在阈值或破坏性操作后执行，避免频繁重写 |
| D-06 | 去重按 `hash` + 时间去重窗口 | 反复复制同一内容不刷屏，但「最近用过」能体现（刷新 updatedAt） |
| D-07 | 采集逻辑与 Electron API 解耦、时钟可注入 | 使去重与保留策略可被 `node:test` 直接覆盖 |
| D-08 | 自动粘贴用系统自带能力发送 Ctrl+V，失败即降级 | 保持运行时零依赖；提权窗口无法注入时给明确提示 |
| D-09 | 启动时不采集剪贴板已有内容 | 避免每次开机把陈旧剪贴板塞进历史 |
| D-10 | 弃用 Vite，渲染层改用 tsc 编译 | 本机沙箱禁止 Node 派生进程，Vite 的原生工具链报 EPERM 无法工作；本应用渲染层只有少量 TS 文件，无需 `node_modules` 解析与代码分割，tsc 输出即可直接由 Electron 以 ESM 加载 |
| D-11 | preload 构建为自包含单文件 | sandbox 下的 preload 无法加载相对模块（C-01），必须把共享常量内联；构建脚本会在内联失败时**直接报错**，绝不静默产出缺常量的 preload |
| D-12 | 提供 `--smoke` 冒烟自检 | 图形界面无法在自动化环境中肉眼确认，故让应用自身在渲染层加载完成后校验 preload 通路并返回退出码，作为可脚本化的验收手段 |
| D-13 | **剪贴板访问全部改为异步** | Electron 44 的 `clipboard` 已改为异步 API：`readText()` / `read()` / `writeText()` / `has()` 都返回 Promise。**旧同步与图片方法 `readImage()` / `writeImage()` / `availableFormats()` 已被彻底移除**（运行时实测为 `undefined`）。故采集器不再依赖「图片对象」，改为从剪贴板项按 MIME 类型取 Blob 再转字节 |
| D-14 | 图片宽高改为**直接解析 PNG 头部**（IHDR） | 上游 API 变更后不再有能返回尺寸的图片对象（`NativeImage` 亦随之从剪贴板通道消失）。PNG 头部结构固定（签名 + IHDR 的宽高各 4 字节大端），自己解析比引入图像库轻量得多，且天然规避沙箱与依赖问题 |
| D-15 | 剪贴板「序列号」判据降级为**可选** | `availableFormats()` 已不存在，`CF_CLIPBOARD_SEQUENCE` 无法探测。故序列号不再是必需判据，仅在能拿到时使用；**去重正确性改为完全由内容比对（以及 store 的哈希 + 时间窗口）保证** |
| D-16 | IPC 统一用 `{ ok, data }` / `{ ok: false, error }` 信封 | 主进程所有处理器一律以抛异常表示失败，由 `invokeSafely` 统一包装。渲染层只需判断 `ok`，不必区分「抛异常」与「返回失败对象」两种风格 |
| D-17 | 提供无界面的**集成自检**（`src/main/smoke.ts`） | 图形界面无法在自动化环境里肉眼确认，但「IPC 处理器能否正确读写真实 store」可以。自检用采集器的测试接缝注入可控内容，然后调用与界面**完全相同**的处理器走完整流程，把「界面能工作」变成可断言的退出码 |
| D-18 | 自检运行在**临时数据目录** | 自检会写入数据，故 `scripts/run-electron.mjs --smoke` 会把 `CLIPHISTORY_DATA_DIR` 指向 `os.tmpdir()`，保证**绝不污染用户真实历史** |
| D-19 | 图片缩略图先用占位图 | 渲染层目前拿不到图片本体的路径（IPC 契约只回相对路径，且沙箱渲染层不能直接读文件）。Phase 6 再接入安全的自定义协议；当前显示占位图与真实尺寸，**绝不假装有图** |
| D-20 | 界面用 `body.dataset.bootState = 'ready'` 标记初始化完成 | 自动化验收需要一个**稳定、与文案无关**的就绪信号。若靠判断状态栏文字，改一次文案就会让自检误判；因此用数据属性标记，自检据此断言界面是否真的装配完成 |

## 7. 性能与容量预算

| 项 | 预算 |
|---|---|
| 轮询开销 | 每 800ms 一次读取，忽略不计 |
| 条目上限 | 默认 10000 条，超出按「先删最旧未置顶」收缩 |
| 单条文本上限 | 10 万字符（超出截断并标注） |
| 列表加载 | 只读索引（不含全文），1 万条内应 < 200ms |
| 图片存储 | 位于系统用户数据目录，由保留策略与孤儿回收共同约束增长 |

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 模拟按键被安全策略拦截 | 自动粘贴失效 | 失败即降级为「仅复制 + 明确提示」，不静默失败 |
| 提权窗口无法粘贴 | 功能不可用 | 文档与设置页明示限制 |
| 索引文件损坏 | 历史丢失 | 逐行解析、跳过坏行并记录日志，单行损坏不影响整库 |
| 中文路径编码问题 | 打包/工具链异常 | 数据目录用系统 userData（ASCII）；文档日志文件名用英文 |
| 图片无限增长 | 占盘 | 保留策略 + 孤儿图片回收 + 条目上限 |
| 重复复制造成列表噪音 | 体验差 | 去重窗口 + 刷新时间戳而非新增条目 |
