# 技术方案

> 本文件是本项目技术栈、模块职责与接口契约的唯一真源。
> 动代码结构、引入新依赖之前，必须先读本文件并同步更新它。

---

## 1. 技术选型与依据

| 项 | 选择 | 依据 |
|---|---|---|
| 运行时 | **Electron** | 本机已具备 Node v24.21.0 / npm 11.19.0 / pnpm 12.4.1；**无 rustc/cargo、无 MSVC 生成工具**，故 Tauri 需额外安装重型工具链，不采用；**无 .NET SDK**，故 WPF/WinUI 不采用。Electron 自带剪贴板与托盘能力，开箱可用。 |
| 语言 | **TypeScript** | 类型约束数据格式与 IPC 契约，降低跨进程出错概率 |
| 构建 | **Vite**（仅渲染层） + **tsc**（主进程/preload） | Vite 处理渲染层打包，主进程保持 CommonJS 直出，简单可控 |
| 渲染层框架 | **无框架**（原生 DOM + CSS + TS） | 界面规模小（单列表 + 少量弹层），引入 React/Vue 收益低、依赖多 |
| 打包 | **electron-builder** | 一把产出 NSIS 安装包 + 免安装 exe |
| 存储 | **本地文件**（NDJSON 索引 + 独立文件） | 1–5 天量级下性能足够；零原生模块，规避 better-sqlite3 的 ABI 重编译风险 |
| 运行时依赖 | **仅 electron** | 精简依赖面，安全与可维护性优先 |

## 3. 进程与职责边界

| 进程 | 职责 | 绝不负责 |
|---|---|---|
| 主进程 main | 剪贴板轮询、数据读写、托盘、窗口生命周期、IPC 处理、过期清理 | 不参与 DOM 渲染 |
| 预加载 preload | 用 `contextBridge` 暴露白名单方法 | 不暴露 `ipcRenderer` 原始对象、不暴露 Node 模块 |
| 渲染层 renderer | 展示列表、搜索筛选、卡片交互、设置面板 | 不直接访问文件系统、不直接操作剪贴板 |

安全配置（固定，不得放宽）：

```ts
webPreferences: {
  contextIsolation: true,
  nodeIntegration: false,
  sandbox: true,
  preload: <path to preload.js>,
}
```

## 4. 数据流

```
Windows 剪贴板
   │  （每 800ms 轮询）
   ▼
clipboard-watcher ──► 序列号/内容判定 ──► 去重与忽略规则 ──► store.add()
   │                                                          │
   │                                                          ▼
   │                                            index.ndjson + content/<id>.txt + images/<hash>.png
   │                                                          │
   │  webContents.send('entries:changed')                     │
   ▼                                                          ▼
renderer  ◄──── IPC 查询（列表/详情/搜索）───────────── main IPC handlers
   │
   └─ 用户点「复制 / 粘贴」──► paste.ts ──► 写回剪贴板（记录预期序列号）──► 可选模拟 Ctrl+V
```

## 5. IPC 契约

通道名集中在 `src/shared/constants.ts`，**新增通道必须同步更新本节**。

### 5.1 渲染层 → 主进程（invoke，均有返回值）

| 通道 | 入参 | 返回 | 用途 |
|---|---|---|---|
| `entries:list` | `{ query?: string; kind?: 'all'\|'text'\|'image' }` | `ClipEntryMeta[]` | 取列表（含预览，不含全文） |
| `entries:get` | `{ id: string }` | `ClipEntryDetail \| null` | 取单条全文/图片路径 |
| `entries:setPinned` | `{ id: string; pinned: boolean }` | `ClipEntryMeta \| null` | 置顶/取消置顶 |
| `entries:delete` | `{ id: string }` | `boolean` | 删除单条 |
| `entries:restore` | `{ entry: ClipEntryDetail }` | `ClipEntryMeta` | 撤销删除 |
| `entries:clear` | `{ keepPinned: true }` | `{ removed: number }` | 清空（保留置顶） |
| `paste:copy` | `{ id: string }` | `{ ok: boolean; error?: string }` | 仅复制到剪贴板 |
| `paste:toActive` | `{ id: string }` | `{ ok: boolean; mode: 'auto'\|'copyOnly'; error?: string }` | 写回并尝试自动粘贴 |
| `settings:get` | — | `Settings` | 读设置 |
| `settings:update` | `Partial<Settings>` | `Settings` | 改设置（含期限），返回校验后的结果 |

### 5.2 主进程 → 渲染层（send）

| 通道 | 载荷 | 用途 |
|---|---|---|
| `entries:changed` | — | 通知列表数据已变，渲染层重新拉取 |
| `watcher:state` | `{ paused: boolean }` | 暂停/恢复状态变化 |

**契约纪律**：所有入参在主进程侧必须做类型与范围校验；渲染层传参不可信。

## 6. 关键实现决策

| 编号 | 决策 | 理由 |
|---|---|---|
| D-01 | 剪贴板采用 800ms 轮询 | Windows/Electron 无可靠原生变更事件（见 LIM-02） |
| D-02 | 用剪贴板序列号 + 内容哈希双重判定防自触发 | 软件写回剪贴板时记录预期序列号，下一轮比对时跳过 |
| D-03 | 文本全文与索引分离存储 | 索引保持小体积，列表加载快；全文按需读取 |
| D-04 | 图片按内容哈希命名并复用文件 | 重复图片天然合并，不重复占盘 |
| D-05 | 索引用 NDJSON 追加 + 阈值压缩 | 追加为 O(1) 写入；压缩仅在阈值或破坏性操作后执行，避免频繁重写 |
| D-06 | 去重按 `hash` + 时间去重窗口 | 反复复制同一内容不刷屏，但「最近用过」能体现（刷新 updatedAt） |
| D-07 | 采集逻辑与 Electron API 解耦、时钟可注入 | 使去重与保留策略可被 `node:test` 直接覆盖 |
| D-08 | 自动粘贴用系统自带能力发送 Ctrl+V，失败即降级 | 保持运行时零依赖；提权窗口无法注入时给明确提示 |
| D-09 | 启动时不采集剪贴板已有内容 | 避免每次开机把陈旧剪贴板塞进历史 |

## 7. 性能与容量预算

| 项 | 预算 |
|---|---|
| 轮询开销 | 每 800ms 一次读取，忽略不计 |
| 条目上限 | 默认 10000 条，超出按「先删最旧未置顶」收缩 |
| 单条文本上限 | 10 万字符（超出截断并标注） |
| 列表加载 | 只读索引（不含全文），1 万条内应 < 200ms |
| 图片存储 | 位于系统用户数据目录，由保留策略与孤儿回收共同约束增长 |

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 模拟按键被安全策略拦截 | 自动粘贴失效 | 失败即降级为「仅复制 + 明确提示」，不静默失败 |
| 提权窗口无法粘贴 | 功能不可用 | 文档与设置页明示限制 |
| 索引文件损坏 | 历史丢失 | 逐行解析、跳过坏行并记录日志，单行损坏不影响整库 |
| 中文路径编码问题 | 打包/工具链异常 | 数据目录用系统 userData（ASCII）；文档日志文件名用英文 |
| 图片无限增长 | 占盘 | 保留策略 + 孤儿图片回收 + 条目上限 |
| 重复复制造成列表噪音 | 体验差 | 去重窗口 + 刷新时间戳而非新增条目 |
