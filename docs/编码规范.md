# 编码规范

> 本文件是本项目代码风格与工程纪律的唯一真源。**每次写代码前必读。**

---

## 1. 基本纪律

1. **不擅自引入新依赖**。引入任何运行时依赖前必须：说明用途、给出不加它的替代方案、说明体积与安全影响，经确认后写入 [`技术方案.md`](技术方案.md) 再安装。
2. **不跨阶段开发**。当前阶段只做当前阶段的事，后续阶段的功能不提前塞进来。
3. **不修改工作区外的文件**（含 `~/.dsh`、系统配置）。
4. **不留下死代码**：被替换的旧实现直接删除，不用注释「保留备用」。
5. **凡假设必验证**：涉及平台行为（剪贴板、托盘、模拟按键）的结论必须有实测或可引用依据，不靠猜测。

## 2. TypeScript

- `strict: true`；禁止 `any`（确需时用 `unknown` + 类型收窄，并在同一行注释说明原因）。
- 禁止非空断言 `!`，除非紧接一次显式存在性检查并不可能失败。
- 对外部数据（文件内容、IPC 入参、剪贴板内容）一律视为 `unknown`，**必须校验后再用**。
- 导出类型优先，接口命名用 `I` 以外的前缀无强制，但同一模块内保持一致。
- 公共函数必须写返回类型；简单内部箭头函数可省略。

## 3. 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 文件/目录 | kebab-case；renderer 与 test 例外见下 | `clipboard-watcher.ts` |
| 类型/接口 | PascalCase | `ClipEntry`、`Settings` |
| 函数/变量 | camelCase | `readIndex()`、`retentionDays` |
| 常量 | UPPER_SNAKE_CASE | `DEFAULT_RETENTION_DAYS`、`IPC_CHANNELS` |
| 布尔量 | `is`/`has`/`should` 前缀 | `isPinned`、`hasImage` |
| IPC 通道字符串 | `域:动作` | `entries:list`、`paste:copy` |

中文仅用于：界面文案、注释、文档、日志消息。**标识符一律英文**。

## 4. 模块组织

- 一个文件一个主要职责；文件超过约 400 行考虑拆分。
- 主进程模块**不得**直接操作 DOM；渲染层**不得**直接访问文件系统或剪贴板。
- 采集、保留策略等纯逻辑必须与 Electron API 解耦（依赖注入：传时钟、传读取函数），以保证可单测（见 D-07）。
- 跨进程共用的类型与常量放 `src/shared/`，**不得**在 main 与 renderer 各自复制一份。

## 5. 错误处理

- **不吞异常**。捕获后必须：记录日志，并向用户给出可行动的提示或返回明确的失败结果。
- 文件读写、JSON 解析等可能失败处必须显式处理；禁止 `catch {}` 空块。
- 写入采用「临时文件 + 原子替换」，见 [`存储与数据格式规范.md`](存储与数据格式规范.md) §2。
- IPC 处理器必须捕获异常并返回 `{ ok: false, error }`，不得让渲染层收到未处理的 rejection。
- 日志分级：`error`（影响功能）、`warn`（可继续但异常）、`info`（关键流程）；**禁止记录剪贴板的完整内容**（隐私），只记类型、长度、哈希前 8 位。

## 6. 剪贴板与安全

- 渲染层安全配置固定：`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`。**任何情况下不得放宽**。
- preload 只暴露**白名单方法**，绝不暴露 `ipcRenderer` 原始对象、`require`、`process`。
- 所有 IPC 入参在主进程侧做类型与范围校验。
- 文本与图片内容只在本地磁盘流转，**不发起任何网络请求**。
- 日志、错误信息中不得包含用户剪贴板的完整原文。

## 7. 注释

- 注释解释**为什么**，不解释**做什么**（代码本身说明做什么）。
- 每个模块顶部一段简短职责说明。
- 涉及平台怪癖、跳过逻辑、经验性常量（如轮询间隔、去重窗口）必须注释来源与理由。
- 不留 `TODO` 而无对应待办：写 `TODO(devlog/待办事项.md#<条目>)`。

## 8. CSS

- 颜色、圆角、间距、字号**只能**用 [`设计规范.md`](设计规范.md) §2 的令牌，禁止硬编码。
- 类名 kebab-case，语义化（`.entry-card`、`.pin-badge`），不用表现性命名（`.pink-box`）。
- 优先 Flex/Grid；不用内联样式（动态计算宽度等例外）。
- 必须处理 `prefers-reduced-motion`。

## 9. 提交与变更

- 一次提交只做一件事，信息格式：`<type>(<scope>): <中文简述>`，type ∈ `feat|fix|docs|refactor|test|chore`。
- 每个阶段收尾提交一次；提交前必须 `npm run typecheck` 与 `npm test` 通过。
- 不得提交 `node_modules/`、`dist/`、`release/`、日志、用户数据。
- 不得提交密钥、令牌、个人路径。

## 10. 自检清单（每次改完代码问自己）

- [ ] 类型检查通过？测试通过？
- [ ] 非法输入/缺失文件/损坏数据是否都有处理？
- [ ] 是否有硬编码的颜色或魔法数字？
- [ ] 是否引入了未确认的依赖？
- [ ] 是否触碰了工作区外文件？
- [ ] 日志里是否意外记录了剪贴板原文？
- [ ] 相关文档与开发日志是否已同步更新？
